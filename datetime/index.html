Source instant

Date-only, SQL timestamps and JDN use the browser-local zone. An explicit ISO offset selects an instant. The display zone changes presentation only.

Instant & civil

Julian & Unix

App JDN is an integer Gregorian day derived from the browser-local date. It is independent of the display zone. This is not fractional astronomical JD.

SQL formats

“Local” always means browser local. Unzoned SQL strings do not identify an instant. Examples show text formats, not database execution or range validation; use parameters in real queries.

Intl uses the selected display zone and locale. Relative time compares the instant to now; months and years use approximate durations.

Parsing rules & important differences
  • After removing TIMESTAMP / TIMESTAMPTZ or ODBC {ts '…'} wrappers, 8 digits are interpreted as SQL Server yyyymmdd.
  • Other integers: |n| ≥ 10¹¹ → Unix milliseconds; |n| ≥ 10⁹ → Unix seconds; 0 < n < 4,000,000 → JDN at local midnight. Other integers are rejected. Use ISO for timestamps close to the Unix epoch.
  • ISO / SQL civil dates are checked for invalid calendar values. Fractional seconds are truncated to milliseconds. Free text falls through to browser-dependent Date.parse.
  • Browser-local times in daylight-saving gaps move forward; repeated times select the earlier occurrence. Use an explicit offset to distinguish repeated times.
  • The Julian conversion uses the proleptic Gregorian calendar, including before its historical adoption. Very old dates can have historical zone offsets. The token lab shows offsets at minute precision.
  • “Today 00:00” means today in the browser zone. Display-zone changes do not reinterpret your source.
