How formatting and comparison work
  • Data-changing edits are formatted with two spaces after a short pause. Cosmetic changes, comments, trailing commas and key reordering remain as typed. Bare identifier keys may be quoted without otherwise reformatting.
  • Sort keys recursively orders object keys using localeCompare and formats the document; array order is preserved. Sort both helps align documents whose key order differs.
  • Objects compare without key order; arrays compare by index. Missing entries, types, values and array lengths are reported separately. Paths with unusual keys use brackets and quoted strings.
  • Errors keep your text intact and highlight the first failing line. Valid JSONC uses original token positions for accurate path highlighting, even without pretty-printing.
  • Tab inserts two spaces. Lock scroll aligns a nearby shared path around the viewport middle; missing paths align to their nearest existing parent. Comments are removed only when formatting is needed or sorting is requested.
  • Parsing uses JavaScript numbers: integer precision beyond 2⁵³ − 1 is not guaranteed; numeric spelling is not compared. Duplicate object keys follow JSON.parse semantics: the last value wins.
Everything stays in this browser page. Nothing is saved or sent to a server.
